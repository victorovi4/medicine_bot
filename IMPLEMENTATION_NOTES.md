## 🔧 Ключевые технические решения

### Telegram: Кнопки вместо команд
**Проблема:** Команды `/batch`, `/done`, `/cancel` неудобны для пользователя.

**Решение:** ReplyKeyboard с кнопками:
| Кнопка | Команда |
|--------|---------|
| 📎 Много фото | `/batch` |
| ✅ Готово | `/done` |
| ❌ Отмена | `/cancel` |
| 📊 Статистика | `/status` |
| 📋 Последние | `/last` |

**Поведение клавиатуры:**
- При `/start` — основные кнопки: 📎 Много фото, 📊 Статистика, 📋 Последние
- При "📎 Много фото" — переключается на: ✅ Готово, ❌ Отмена
- После любого действия — возвращается основная клавиатура

### Telegram: Многостраничные документы
**Проблема:** Пользователь отправляет несколько фото одного документа.

**Решение:** Кнопка "📎 Много фото" для ручной группировки:
```
[📎 Много фото]  — начать сбор (создаёт маркер __batch_marker__)
[фото 1]         — добавляется в BatchPending
[фото 2]         — добавляется в BatchPending
[✅ Готово]      — объединить в PDF и обработать
```

**PDF-объединение (pdf-lib):**
- Все фото скачиваются из Vercel Blob
- Создаётся PDF с помощью `pdf-lib`
- Каждое фото = отдельная страница (размер страницы = размер фото)
- Порядок страниц = порядок добавления (по `receivedAt`)
- Готовый PDF загружается в Blob
- AI анализирует все изображения одним запросом

**Почему не media_group_id:**
- Telegram присваивает media_group_id только при отправке нескольких фото разом из галереи
- При пересылке из другого чата media_group_id теряется
- Кнопка "📎 Много фото" работает в любом случае

### Telegram: Проверка дубликатов
**Проблема:** Один документ может быть добавлен дважды.

**Решение v2 (улучшенное):** После AI-анализа ищем похожие документы (±7 дней):

| Критерий | Порог | Уверенность |
|----------|-------|-------------|
| Тот же врач + та же дата | точно | 90% |
| Схожее заключение (fuzzy) | ≥70% | по схожести |
| Совпадение keyValues | ≥80% | по схожести |
| Схожее название | ≥50% | по схожести |

**Модуль:** `src/lib/duplicates.ts`
- `checkDuplicate()` — проверяет пару документов
- `findDuplicate()` — ищет дубликат среди списка
- `calculateSimilarity()` — коэффициент Жаккара для текста
- `compareKeyValues()` — сравнение ключевых показателей

Если найден дубликат — показываем сообщение со **ссылкой на существующий документ**, **причиной** и inline-кнопки:
```
⚠️ Найден похожий документ!

📋 Новый: Анализ крови
📅 2026-01-20

📋 Существующий: Анализ крови
📅 2026-01-18
🔗 https://site.com/documents/xxx   <-- ссылка на дубликат

[➕ Добавить как новый]
[🔄 Заменить существующий]
[❌ Отмена]
```

**Таблицы:**
- `BatchPending` — временное хранение страниц при `/batch`
- `PendingDocument` — документ ожидающий подтверждения (для дубликатов)

### AI: Парсинг JSON
**Проблема:** Claude иногда возвращает невалидный JSON или обёртывает в markdown.

**Решение:** Многоуровневый парсинг:
1. Убираем ```json обёртки
2. Пытаемся JSON.parse напрямую
3. Ищем `{...}` в тексте через regex
4. Если всё не удалось — создаём базовый документ с тегом "требует проверки"

### AI: Заключение и рекомендации
**Требование:** Заключение врача — дословно, рекомендации — список задач.

**Реализация:**
- Поле `conclusion` — дословная цитата из документа
- Поле `recommendations` — массив строк
- В промпте явно указано: "извлекай ДОСЛОВНО, не перефразируй"

### Document
```prisma
model Document {
  id              String    @id @default(uuid())
  date            DateTime
  category        String    // заключения, анализы, исследования, другое
  subtype         String    // консультация, кровь, узи, кт, пэт-кт...
  title           String
  doctor          String?
  specialty       String?
  clinic          String?
  summary         String?   // AI-резюме
  conclusion      String?   // Заключение врача (дословно)
  recommendations String[]  // Рекомендации (список)
  content         String?
  fileUrl         String?
  fileName        String?
  fileType        String?
  tags            String[]
  keyValues       Json?
  createdAt       DateTime
  updatedAt       DateTime
}
```

**Категории и подтипы:**
| Категория | Подтипы |
|-----------|---------|
| заключения | консультация, выписка, направление |
| анализы | кровь, биохимия, онкомаркеры, моча, гистология |
| исследования | узи, кт, мрт, пэт-кт, рентген, экг |
| другое | другое |

### BatchPending
```prisma
model BatchPending {
  id         String   @id @default(uuid())
  chatId     BigInt
  fileUrl    String   // URL файла или "__batch_marker__"
  fileType   String
  receivedAt DateTime @default(now())
}
```

### PendingDocument
```prisma
model PendingDocument {
  id           String   @id @default(uuid())
  chatId       BigInt
  messageId    Int?     // ID сообщения с кнопками
  documentData Json     // Все поля документа
  duplicateId  String?  // ID существующего дубликата
  createdAt    DateTime
  expiresAt    DateTime // Автоудаление через 1 час
}
```

## 🔧 Отладка и настройка

### Установка Telegram Webhook
**Проблема:** Inline-кнопки (callback_query) не работают.

**Причина:** Webhook был установлен без `allowed_updates: ['message', 'callback_query']`.

**Решение:** Переустановить webhook:
```
https://medicine-bot-4xqt.vercel.app/api/telegram/setup?set=true
```

**Проверка текущего webhook:**
```
https://api.telegram.org/bot<TOKEN>/getWebhookInfo
```

Должно быть:
```json
{
  "allowed_updates": ["message", "callback_query"]
}
```

## ⚠️ Известные ограничения

1. **AI-анализ рукописных документов** — качество зависит от разборчивости почерка
2. **Большие PDF** — могут превышать лимиты токенов Claude
3. **Telegram file size** — Telegram ограничивает размер файлов (20 MB для ботов)
4. **PendingDocument expiration** — нет автоочистки просроченных записей (нужен cron)
5. **Webhook callback_query** — при изменении allowed_updates нужно переустановить webhook

- **Модель Procedure** — новая таблица для хранения процедур:
  - Типы: `hemotransfusion`, `surgery`, `manipulation`, `puncture`, `laparocentesis`
  - Поля: дата, название, детали (volume, bloodType, component)
  - beforeValue/afterValue — показатели до и после (для гемотрансфузии: гемоглобин)
  - Связь с документом-источником

- **Улучшенный AI-промпт** — теперь извлекает:
  - `procedures` — проведённые процедуры (гемотрансфузии определяются по косвенным признакам)
  - `measurementsDynamics` — динамика показателей за госпитализацию (все значения по датам)
  - Признаки гемотрансфузии: резкий рост Hb (+20 г/л за 1-2 дня) + подготовительные анализы

- **API `/api/procedures`**:
  - GET — список процедур с фильтрами (type, from, to)
  - POST — добавление процедуры вручную

- **Маркеры гемотрансфузий на графике Гемоглобина**:
  - Вертикальные линии с иконкой 💉
  - Информация о количестве переливаний
  - Значения до/после (если есть)

- **UI страницы документа**:
  - Блок "Проведённые процедуры" с фиолетовым оформлением
  - Детали каждой процедуры: дата, название, изменение показателя, группа крови

- **Динамика показателей за госпитализацию**:
  - При импорте выписки/эпикриза сохраняются ВСЕ значения анализов по датам
  - Это позволяет видеть полную картину: Hb 87 → 75 → 108 г/л

- **Алгоритм автодетекции гемотрансфузий** (`src/lib/hemotransfusion-detector.ts`):
  
  **Признаки обнаружения:**
  | Признак | Уверенность |
  |---------|-------------|
  | Резкий рост Hb (+15 г/л за 1-4 дня) | medium |
  | + Критический уровень до (<75 г/л) | high |
  | + Определение группы крови рядом | high |
  | Только группа крови + низкий Hb | low |
  
  **API `/api/procedures/detect`:**
  - `GET` — показать обнаруженные гемотрансфузии (без создания)
  - `POST` — обнаружить и создать записи Procedure
  - `POST {"dryRun": true}` — тестовый запуск без создания
  
  **Пример использования:**
  ```bash
  # Проверить, что будет обнаружено
  curl https://medicine-bot-4xqt.vercel.app/api/procedures/detect
  
  # Создать записи для обнаруженных гемотрансфузий
  curl -X POST https://medicine-bot-4xqt.vercel.app/api/procedures/detect
  ```
  
  **Ручное добавление:**
  ```bash
  curl -X POST .../api/procedures -d '{"date":"2026-01-29","type":"hemotransfusion",...}'
  ```
