# Проверка документов по клиническим рекомендациям Минздрава

## Обзор

Кнопка «Проверить по КР» на странице документа в веб-интерфейсе. Запускает AI-агента-валидатора, который сопоставляет содержимое документа с клиническими рекомендациями (КР) по основному диагнозу пациента и выдаёт структурированный отчёт.

## Контекст

- Каждый инстанс обслуживает одного пациента с одним основным диагнозом
- КР загружаются целиком в контекст Claude (без RAG)
- КР12 (C61 рак простаты) — ~70K токенов, КР144 (C90 миелома) — ~43K токенов
- Контекстное окно Claude 200K: КР + данные документа + контекст пациента = ~100-120K — вмещается

## Архитектура

### Файлы КР

Хранятся как текстовые файлы в `src/data/clinical-guidelines/`:
- `KR12-C61.txt` — Рак предстательной железы (извлечённый текст из PDF)
- `KR144-C90.txt` — Множественная миелома (извлечённый текст из PDF)

При сборке включаются в бандл. Загружаются по `PATIENT.mainDiagnosisCode`.

### API endpoint

`POST /api/kr-check`

**Request body:**
```json
{
  "documentId": "uuid"
}
```

**Response:** streaming SSE (аналогично assessment)
```
data: {"type": "text", "text": "..."}
data: {"type": "done", "result": {...}}
```

**Результат (JSON в done-событии):**
```json
{
  "items": [
    {
      "status": "ok" | "warning" | "error",
      "title": "ПСА контроль выполнен",
      "description": "ПСА 0.068 нг/мл — в пределах нормы",
      "krReference": "КР12 п.5.1: «Контроль ПСА каждые 3-6 мес»"
    }
  ],
  "summary": { "ok": 2, "warning": 1, "error": 2 }
}
```

### AI-агент-валидатор

**Модель:** Claude Haiku (экономия, достаточная точность для сопоставления)

**System prompt:**
- Роль: эксперт по проверке медицинских документов на соответствие КР
- Полный текст КР (по диагнозу пациента)
- Инструкции по формату вывода (JSON)

**User prompt:**
- Данные документа: title, date, summary, conclusion, recommendations, keyValues, fullText
- Краткий контекст пациента: диагноз, стадия, текущая терапия, последние ключевые показатели

**Что проверяет:**
1. Соответствие обследований — проведены ли рекомендованные КР исследования для данной стадии
2. Соответствие назначений — препараты и дозировки vs КР
3. Сроки контроля — соблюдены ли рекомендованные интервалы наблюдения
4. Пропущенные исследования — что по КР должно быть назначено/проведено

### UI

**Страница документа (`/documents/[id]`):**
- Кнопка «📋 Проверить по КР» рядом с «Редактировать»
- Зелёный градиент (emerald), аналогично assessment
- При нажатии — streaming загрузка результата
- Результат отображается как карточка под summary документа

**Карточка результата:**
- Заголовок: «Проверка по КР12 «Рак предстательной железы»»
- Пункты с цветовой индикацией:
  - Зелёный (✅ ok): соответствует КР
  - Жёлтый (⚠️ warning): требует внимания
  - Красный (🔴 error): расхождение с КР или пропущено
- Каждый пункт: title + description + цитата из КР (курсив)
- Итоговая строка: N соответствует / N внимание / N расхождений

**Состояние:**
- Результат НЕ кэшируется в БД (по запросу, каждый раз свежий)
- Во время генерации — индикатор загрузки
- Кнопка доступна только если `PATIENT.mainDiagnosisCode` совпадает с имеющимися КР

### Ограничения

- Работает только для диагнозов, по которым загружены КР (C61, C90)
- Не является медицинским документом — disclaimer аналогичный assessment
- maxDuration: 60s (Vercel Hobby) — Haiku + один документ должен уложиться
- КР встроены в бандл как текстовые файлы (не скачиваются в рантайме)

### Зависимости
